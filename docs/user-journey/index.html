End-to-end test · 4 October 2026 · run again 16–17 October

The MigraTrack user journey on iPhone and Apple Watch

The test starts with a clean install on both devices. The user meets Siri before setup, reads the welcome screen and the terms, and completes onboarding. Then the user logs attacks on the iPhone, on the watch and with Spotlight, opens the watch logger from the watch face and from the Smart Stack, reads the charts, and exports a report. Steps 19–24 show the Insights calendar, Edit Episode and logging on a past day. Step 25 deletes all data. After each action I compared the SQLite databases on both devices. Click a screenshot to enlarge it.

On 16 and 17 October I ran all 25 steps again on the build of main at 9cf4720. Since the last run, the app got a dot-grid mark in the header, a new icon, ICHD-3 onboarding texts, Health texts for last night's sleep only, and a doctor reminder on the last onboarding step. Possible triggers are new in the Log form, in Insights and in the report. The run started at 23:30 on 16 October and continued after midnight, so some steps happen on 17 October. The screenshots of the complications (step 12) and of the Control tap stay from 13 October, because these screens did not change. The run found four small faults. After their fix, I took the Export screen, the first day in Insights and page 2 of the PDF again on 17 October.

Notes

What I noticed

No step failed, and no data was lost. Below are the four faults that this run found and that are now fixed, two design notes, one platform limit and the simulator details.

FixedFour small faults of this run

  • The Medication Logs toggle in Export promised intake times. It now says "Dosages and usage totals".
  • The PDF of 11 episodes had a page 3 with only the disclaimer. The line now uses the footer space of the last page.
  • Insights said "1 of 3 episode has no triggers noted". It now says "1 of 3 episodes has", and the PDF uses the same text.
  • A bar with only attack days showed a green part. It is now all pink.

DesignMonths in 6M and Y look similar

The pink part of a bar stays at 14% or more, so that one migraine day stays visible. Thus months with 1 and with 4 migraine days look the same. A smaller minimum or the number of days above the bar can help.

DesignThe calendar mockups do not show all behavior

The mockups do not show the start time, the month change and a day with several attacks. The app uses system controls: the date picker in "Episode Start", the month wheels and the alert that asks for the attack. The day card has no duration, because the app does not record an end time.

watchOSThe complication and the Control only open the app

On the watch face, watchOS does not run a button action, it only opens the app. An action in the Smart Stack runs in the extension, and the extension cannot reach the iPhone. Thus each tap opens Pain Intensity, and the log goes to the iPhone at once.

SimulatorNot related to the app

  • After simctl install on the watch, the iPhone saw the watch app as not installed. A second install of the iPhone app fixed it, and the data came at once.
  • The Sleep switch in the HealthKit sheet does not react to a tap, and Select All did not help in this run. Read access stays hidden from the app, so the row shows "Not recorded" in both cases.
  • In Always On mode, the watch does not take taps.
  • The home screen and the Spotlight result (steps 3 and 16) are from the iPhone 18 Pro of 16 October, without the Fitness icon near MigraTrack.
  • simctl openurl does not work on the watch, so I checked the complication link with a tap on the face.

Not checkedNeeds a real device

  • The Control in the watch Control Center: the simulator does not open it. The Smart Stack Control works, step 13.
  • The Digital Crown: my tool cannot turn it. The watch logs have the preset intensity 6.
  • Real sleep data from Apple Health.
  • The transferUserInfo queue: it does not arrive in the simulator, so I checked the direct message.
